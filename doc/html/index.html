MBI_SDK Documentation

MBI Software Development Kit (SDK)

Overview

TOF LC-IM-MS Data

The data present in an .MBI file (generally) represents the data acquired during a single LC-IM-MS acquisition experiment, producing 4-dimensional data (LC, IM, MS, Intensity). Details of these dimensions are summarized below.

Dimension Raw Unit Converted Unit Time Scale MBI Collection*
LC Retention Time Seconds - Minutes Frame Collection
IM Arrival Time CCS Milliseconds - Seconds Scan Collection
MS Flight Time m/z Nanoseconds - Microseconds Gate Collection

*Collection objects will be described in more detail below.

A single file object contains multiple frames (SLIM injection events). Each frame represents a collection of scans (Flight Tube pulse events). Each scan represents a collection of samples (signal digitization events). Each sample has an associated intensity magnitude (the amount of signal detected). In this way, a single frame can be represented as a [Scan, Sample, Intensity] cube, shown below:

The API enables making arbitrary selections in each dimension to extract data. It also allows for operations such as Summing and Averaging to be performed on each of the dimensions. For instance, if the entire range of Scans in the above cube were selected and summed, the result would be a 2D relationship between samples and intensity (better known as a (summed) mass spectrum). Conversely, if the entire range of samples in the above cube were selected and summed, the result would be a 2D relationship between scans and intensity (better known as a (total) mobiligram).

While we cannot draw a cube that demonstrates all 4 dimensions, there is rarely ever a single "DataCube" (frame) in our data files. You could imagine them as two 3D spaces disjoint, but aligned. In this way, summing them produces an identical space as the above image, but with a stretched intensity dimension.

Data Access

Collections

Each of the 4 dimensions specified above can be accessed by making "selections" from the outer dimension. This produces a "collection" of objects that can be further manipulated. For example, a collection of frames can be retrieved from a file using MBIFile.GetFrames(). Similarly, a collection of scans can be retrieved from a file using Frame.GetScans(), etc.

Deferred Loading

When an MBIFile object is initialized, it creates a private index of the file, loading all metadata and defers the loading of the spectrum data. As a frame (or set of frames) are accessed, they are "loaded," which also creates a private index of the frame and loads spectral data. A Frame object can be unloaded from memory using Unload(). If a frame is unloaded, all of its scans are removed from memory.

Metadata

Each MBIFile object contains metadata, which can be accessed via MBIFile.GetGlobalMetadata(). The returned GlobalMetadata object can then be queried for the value of certain keys. In addition, the MBI file object contains functions to access global metadata. Similarly, each frame contains a FrameMetadata object which carries frame-level metadata.

Data Reading

An MBIFile object can be initialized to read data from an MBI file. Once initialized, frames can be loaded and the spectral data accessed. MBIFile objects have access to Retention Time at a frame by frame level. Frame functions have access to Arrival Time for each scan in the frame. Individual intensities can also be read for more in-depth analysis.

Dependencies

This API depends on HDF5 version 1.12.2 (hdf5-1.12.2-Std-win10_64-vs16), which is required for the MBI_SDK to function at runtime. MBI_SDK.zip has included this HDF5 version in headers and lib folders.
